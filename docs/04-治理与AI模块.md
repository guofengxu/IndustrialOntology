# 04 · 治理与 AI 模块（`wp-governance`、`wp-ai`）

> 需求来源：`Ontology/docs/architecture-plan.md` v0.4 第 5.3、5.4 节（建模与版本管理、发布校验、模型注册）。
> 技术：spring-ai-alibaba `graph-core`（StateGraph）、`agent-framework`（ReactAgent）；仅这两个模块引入其 BOM。
> 阶段：`wp-governance` 在 P3；`wp-ai` 在 P4，`webprotege.ai.enabled=false` 时不装配任何 bean。

---

## 1. `wp-governance` 总体

```
governance/
├── version/      快照标签：打标签、列表、对比、回滚
├── mapping/      YARRRML 映射规则：按 type 版本化存储与编辑
├── release/      发布流水线：StateGraph 定义、节点实现、运行记录、SSE 进度
├── registry/     不可变产物存储、/registry REST、webhook 订阅与通知
└── config/       GovernanceAutoConfiguration（@ConditionalOnProperty webprotege.governance.enabled）
```

依赖：`wp-app`（修订、下载重建本体、事件）、`spring-ai-alibaba-graph-core`、ROBOT（`org.obolibrary.robot:robot-core`，与 OWL API 4.5.x 兼容的版本）、Apache Jena（`jena-shacl`）、WIDOCO（命令行 jar，进程外调用）、HTTP 客户端（调用 mapping-service 试运行接口）。

### 1.1 Mongo 集合（新增）

| 集合 | 字段 |
|---|---|
| `OntologyVersions` | `projectId`、`tag`(semver)、`revisionNumber`、`versionIri`、`notes`、`createdBy`、`createdAt` |
| `MappingRules` | `projectId`、`type`(如 `ind.telemetry.opcua.v1`)、`version`、`yarrrml`、`rml`(编译后)、`schemaRef`(Apicurio 引用)、`ontologyVersionRange`、`createdBy`、`createdAt` |
| `Releases` | `_id`(releaseId)、`projectId`、`tag`、`status`(RUNNING/PASSED/REJECTED/FAILED)、`nodes[{name,status,startedAt,endedAt,reportRef}]`、`artifacts[{name,path,sha256,size}]`、`startedBy`、`startedAt`、`endedAt` |
| `RegistryWebhooks` | `url`、`events[]`、`secret`、`createdAt` |

产物文件：`<data-directory>/registry/<projectId>/<tag>/{ontology.ttl, shapes.ttl, context.jsonld, mappings/<type>/<ver>/{mapping.yarrrml, rml.ttl, meta.json}, docs/, reports/}`，写入后只读。

## 2. 版本标签与对比回滚

- **打标签**：`POST /versions {tag, notes}` → 校验 semver 与单调递增 → 记录当前 HEAD 修订号 → 通过 `ChangeManager` 写入一条修订，把 `owl:versionIRI` 设为 `<ontologyIri>/<tag>`（`FixedChangeListGenerator`）。
- **对比**：`GET /versions/{tag}/diff?against=<tag|revision>`：用 `RevisionManager.getOntologyManagerForRevision` 重建两个版本，计算公理集差（OWL API `OWLOntology.getAxioms()` 差集），以 Manchester 文本输出，按实体分组；复用 `wp-app` P1 预留的 `revisions/diff`。
- **回滚**：`POST /versions/{tag}/rollback` = 生成"把 HEAD 变成该标签修订内容"的变更列表（`RevisionReverterChangeListGenerator` 从 HEAD 逐个反转到目标修订，或直接 diff 生成 add/remove），作为一条新修订写入；不删除历史。

## 3. 发布校验流水线（`StateGraph`）

### 3.1 状态

```java
record ReleaseState(
    String releaseId, ProjectId projectId, String tag, int revision,
    Path workDir,                      // 临时目录：导出的 ontology.ttl、shapes.ttl
    Map<String, NodeReport> reports,   // 每节点报告
    List<Artifact> artifacts,
    boolean rejected, String rejectReason)
```

`OverAllState` 的 key 策略：`reports`、`artifacts` 用追加（`AppendStrategy`），其余替换。

### 3.2 节点与边

```
START
 → exportSnapshot        重建 tag 对应修订的本体，写 ontology.ttl；从项目内 SHACL 本体（约定 IRI 后缀 /shapes）或附属文件导出 shapes.ttl
 → robotReport           ROBOT report（质量门禁：缺 label、命名、重复等），ERROR 级别 → rejected
 → robotReason           ROBOT reason（HermiT 一致性），不一致 → rejected
 → localNameUniqueness   同一局部名映射到多个 IRI → rejected（支撑 n10s IGNORE 策略）
 → shaclTests            Jena SHACL：对 ontology-tests/shacl/{pass,fail} 数据集跑 shapes，pass 必须通过、fail 必须失败
 → mappingRegression     调用 mapping-service 试运行接口（HTTP POST 样例报文 + 规则），失败 → rejected
 → generateArtifacts     ontology-<tag>.ttl、shapes-<tag>.ttl、context-<tag>.jsonld（由本体生成 JSON-LD context）、mappings/、docs/（WIDOCO 进程外）
 → humanApproval         interrupt：等待发布者在 UI 确认（可配置跳过）
 → register              写 Releases/产物目录只读、更新 /registry 索引、发 webhook、可选调用 Neo4j n10s.onto.import（HTTP）
 → END
每个校验节点后接条件边：rejected ? → finalizeRejected → END : 下一节点
```

- `CompileConfig` 使用 Mongo `CheckpointSaver`（graph-core 自带 `MongoSaver`）以便进程重启后恢复到 `humanApproval` 中断点。
- 每个节点用 `GraphLifecycleListener` 推 SSE 进度（`/releases/{id}/stream`），事件 `{node, status, summary}`。
- 节点实现为普通 Spring bean（`NodeAction`），耗时步骤在 `@Async("governanceExecutor")` 内执行；单 JVM 同一项目同时只允许一条发布流水线。
- Mermaid 导出：`GET /api/v1/governance/pipeline.mmd` 返回 `compiledGraph.getGraph(GraphRepresentation.Type.MERMAID)`，作为文档与审计材料。

### 3.3 配置

```yaml
webprotege.governance:
  enabled: true
  robot.profile: ${WP_ROBOT_PROFILE:default}
  shacl.tests-dir: ${WP_SHACL_TESTS:/srv/webprotege/ontology-tests/shacl}
  mapping-service.dry-run-url: ${WP_MAPPING_DRYRUN:http://mapping-service:8000/dry-run}
  widoco.jar: ${WP_WIDOCO_JAR:/opt/widoco.jar}
  neo4j.import-url: ${WP_N10S_IMPORT:}
  human-approval.required: true
```

## 4. 模型注册（`/registry`）

- 匿名只读；`ETag` 为产物 sha256；`Cache-Control: public, max-age=31536000, immutable`。
- `GET /registry/mappings/index` → `{ "<type>": ["1.0.0","1.1.0"] }`；`GET /registry/mappings/{type}/{ver}` → `{yarrrml, rml, schemaRef, ontologyVersionRange, sha256}`。
- `GET /registry/releases` → 发布记录（版本、发布人、时间、状态、报告链接）。
- `POST /registry/webhooks/subscribe {url, events[], secret}`（需 EDIT_PROJECT_SETTINGS）；通知 payload `{event: "release.registered", projectId, tag, artifacts[]}`，HMAC-SHA256 签名头 `X-Wp-Signature`。
- 登记只由流水线 `register` 节点触发，无外部写接口。

---

## 5. 映射规则编辑

- 页面 `/projects/:id/mappings`：按 `type` 列出版本；编辑器为 CodeMirror YAML；保存即新版本（不可覆盖）；字段：适用本体版本区间（semver range）、Apicurio schema 引用。
- 保存时后端用 YARRRML → RML 编译（优先进程外调用 `yarrrml-parser`，或 Java 实现的 `yarrrml-java` 若可用；P3 任务中定）。

## 6. `wp-ai`（P4，可选）

### 6.1 本体助手 Agent

- `ReactAgent.builder().model(chatModel).tools(...)`，`chatModel` 由 Spring AI 提供（DashScope 或 OpenAI 兼容端点，配置决定）。
- 工具（全部只读或"生成提案"）：
  - `lookupEntities(projectId, q)`、`getClassFrame(projectId, iri)`、`getPropertyFrame`、`getIndividualFrame`、`searchEntities`、`getHierarchyChildren`
  - `proposeManchesterFrame(iri, text)`：调用 `check`，返回语法错误或可提交的帧文本
  - `proposeAxioms(turtle)`：解析为 `OntologyChange[]` 预览（**不写入**）
- 人在回路：Agent 产出 `Proposal{changes[], explanation}` → UI 展示差异 → 用户点击"应用"才调用 `PUT frames` / `POST axioms`。Agent 永远没有写权限（其 UserId 为 `agent:<name>`，仅授予 VIEW_PROJECT）。
- 端点：`POST /api/v1/projects/{id}/assistant/threads/{threadId}/messages` SSE 流式（与 spring-ai-alibaba Studio 的 `Flux<ServerSentEvent>` 风格一致，这里用 `SseEmitter` 包装 `Flux`）。
- 记忆：`MemorySaver` 按 threadId；上下文中附带项目前缀表与显示名设置。

### 6.2 MCP Server

- 基于 `io.modelcontextprotocol.sdk:mcp` 的 Servlet/HTTP Streamable 传输，挂 `/mcp`；鉴权沿用 ApiKey。
- 暴露工具：`list_projects`、`search_entities`、`get_class_frame`、`get_individual`、`get_hierarchy_children`、`get_mapping_rule`、`get_registry_release`；全部只读。
- 供 RAG-Openclaw / Industry-RAG 等外部 Agent 检索本体。

### 6.3 配置

```yaml
webprotege.ai:
  enabled: false
  provider: dashscope | openai
  model: qwen-plus
  assistant.max-tool-calls: 20
  mcp.enabled: false
```

## 7. 与 mapping-service / NiFi 链路的接口约定

| 方向 | 接口 | 说明 |
|---|---|---|
| WebProtégé → mapping-service | `POST {dry-run-url}` body `{rules:[{type,version,yarrrml}], samples:[cloudevent…], shapes: "<ttl>"}` → `{ok, failures[]}` | 发布校验 `mappingRegression` 节点 |
| mapping-service → WebProtégé | `GET /registry/mappings/index`、`GET /registry/mappings/{type}/{ver}` | 冷启动 / 热加载 |
| WebProtégé → mapping-service | webhook `release.registered` | 触发热加载 |
| WebProtégé → Neo4j | `CALL n10s.onto.import.fetch(url, "Turtle")` 经 HTTP 事务接口 | 可选，`neo4j.import-url` 配置 |
