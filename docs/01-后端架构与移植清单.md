## 2. 项目级对象图：`ProjectContext`

旧实现用 Dagger `ProjectComponent`（`@ProjectSingleton`）。新实现**不使用 Spring 自定义 scope**，而是显式工厂：

```java
// wp-kernel
public final class ProjectContext implements AutoCloseable {
    ProjectId projectId;
    ProjectIndexes indexes;            // 全部索引实例（见 §3.2），含 RootIndex
    IndexUpdater indexUpdater;
    RevisionStore revisionStore;       // BinaryOWL
    RevisionManager revisionManager;
    HierarchyProviders hierarchies;    // class / object / data / annotation
    DictionaryManager dictionary;      // Lucene 短名字典 + 搜索
    RenderingManager rendering;
    EntityCrudKitHandlerCache crudKits;
    ProjectEventManager events;        // 带 EventTag 的事件桶
    ChangeManager changeManager;       // 实现 HasApplyChanges
    ReadWriteLock lock;                // 项目级读写锁
    Instant lastAccess;
    void close();                      // 关闭 Lucene writer、停止事件清理线程
}
```

- `ProjectContextFactory.create(ProjectId)`：按旧 `ProjectModule`（`<core>/inject/project/ProjectModule.java`，724 行）的 provider 顺序手写构造：目录 → `RevisionStore.load()` → 构造索引 → `IndexUpdater.buildIndexes()` → 层级 Provider → Lucene（若无索引目录则全量建） → `ChangeManager`。
  - 已实现（S1）：应用层协作者（项目详情、前缀、CRUD kit 设置、讨论、标签、关注、创建权限检查、搜索过滤器）通过 `kernel.project.ProjectPorts` 注入，共享线程池通过 `KernelThreadPools` 注入；`close()` 先等待项目读写锁，再按打开的逆序释放（事件清理任务 → Lucene searcher → writer → directory → 等待修订写盘完成），不关闭共享线程池。构造失败时已打开的资源同样释放。
- `ProjectRegistry`（Spring 单例，`wp-app`）：Caffeine `expireAfterAccess(webprotege.project.dormant-time)`，`removalListener` 调 `close()`；`get(projectId)` 加载时按 projectId 加锁，对应旧 `ProjectCache`。
  - 已实现（S3，`app.project`）：Caffeine 只负责判断项目何时空闲，哪个上下文处于打开状态由注册表自己记录，因为 Caffeine 的移除通知是异步的。打开和关闭都在该项目的锁内进行，旧上下文关闭后才打开新的（否则新上下文拿不到 Lucene 写锁）。到期由注册表自己的线程按时触发，并在该线程上关闭项目。另提供 `getIfLoaded`（读取时不算使用，对应旧 `getProjectEventManagerIfActive`）、`close(projectId)` 和 `closeAll()`。Bean 由 `ProjectRuntimeAutoConfiguration` 创建，只在存在 `ProjectPorts`（S4/S5）和 `DataDirectoryLayout` 两个 bean 时生效。
- 应用层服务通过 `ProjectRegistry.get(projectId)` 拿到 `ProjectContext`，再调用其中对象。索引接口依旧按类型取用：`ctx.indexes().get(ClassFrameAxiomsIndex.class)`。

4. 测试：`<core>/.../index/impl/*_TestCase`（约 60 个）全部转 JUnit 5，类名去 `_TestCase` 改 `Test`。

### 3.4 并发与锁

- 每个 `ProjectContext` 一把 `ReentrantReadWriteLock`。读服务取读锁；`ChangeManager.applyChanges` 取 `changeProcessingLock`（串行化变更生成）后再取写锁，与旧实现一致。
- 修订落盘线程、事件清理线程、索引更新线程池：全部由 `wp-app` 的 `KernelExecutors` bean 提供，`ProjectContext.close()` 不关闭共享池。
  - 已实现（S3）：索引更新 10 个线程（同旧），修订落盘 4 个线程（每个项目自己保证写盘顺序），事件清理 1 个线程；线程数可用 `webprotege.kernel.index-update-threads` 和 `revision-write-threads` 配置。

| `EntityDiscussionThreads` | `DiscussionThreadDocument` | `_id`(threadId)、`projectId`、`entity`、`status`、`comments[{id,createdBy,createdAt,updatedAt,body,renderedBody}]` | 原样 |
| `ProjectWebhook` | `WebhookDocument` | `projectId`、`payloadUrl`、`subscribedToEvents[]` | 原样 |
| `UserApiKeys` | `UserApiKeysDocument` | `userId`、`apiKeys[{apiKeyId, apiKey(sha256 hex), createdAt, purpose}]` | 原样；新版生成走 `/api/v1/me/api-keys` |
| `ApplicationPreferences` | `ApplicationPreferencesDocument` | `applicationName`、`systemNotificationEmailAddress`、`applicationLocation{scheme,host,path,port}`、`applicationSettings{accountCreationSetting, accountCreators[], projectCreationSetting, projectCreators[], projectUploadSetting, projectUploaders[], notificationEmailsSetting, maxUploadSize}` | 原样 |
| `EntitySearchFilters` | `EntitySearchFilterDocument` | `projectId`、`filters[]` | 原样 |
| `SlackWebhooks`、`CollectionItemData`、`CollectionDetails`、`FormData`、`EntityGraphSettings` | — | 不读写（`EntityGraphSettings` P4 再定） |

嵌入 `OWLEntity` 的集合（EntityTags、Watches、EntityDiscussionThreads）必须复刻旧 Morphia converter 的存储格式：移植前先用 `mongoexport` 导一条样本固定在测试资源里，写 `OwlEntityMongoCodec` 使新旧文档字节级兼容。

`wp-cli migrate-mongo`：幂等脚本，只做三件事：删除 `className` 字段、为缺失的索引 `ensureIndex`、校验嵌入实体格式并报告异常文档。

## 6. 安全（`wp-api`）

| 关注点 | 设计 |
|---|---|
| 浏览器登录 | 前端 OIDC Authorization Code + PKCE（Keycloak client `webprotege-web`），携带 Bearer JWT 调 `/api/v1/*` |
| JWT → UserId | `preferred_username` claim；首次见到的用户写入 `Users`（realName 取 `name`，email 取 `email`） |
| 系统管理员 | JWT realm role 含 `webprotege.auth.admin-realm-role` → 请求上下文附加 `SYSTEM_ADMIN`（不落库） |
| API Key | `ApiKeyAuthenticationFilter`：`Authorization: ApiKey <key>` → SHA-256 → `UserApiKeys`；成功则构造 `UsernamePasswordAuthenticationToken(userId)`；与 JWT 并存，JWT 优先 |
| 本地兜底 | `webprotege.auth.local-login.enabled=true` 时启用 `/login` 表单（BCrypt，`Users.localPasswordHash` 新字段），仅供 dev 与首个管理员；不迁移旧 MD5 密码 |
| 授权 | 服务层 `AccessManager.require(...)`；控制器不做授权 |
| CSRF | 关闭（Bearer/ApiKey 无状态）；同站 Cookie 不用于认证 |
| `/download`、`/data/*` 兼容层 | 同一 Security 链；允许 `?apiKey=` 查询参数仅用于下载链接（可配置关闭） |

## 7. 可观测与运维

- Actuator：`health`（含 Mongo、数据目录可写检查）、`metrics`、`prometheus`。
- 自定义指标：`wp.projects.loaded`、`wp.project.load.seconds`、`wp.changes.applied`、`wp.change.apply.seconds`、`wp.events.sse.connections`、`wp.search.seconds`。
- 日志 MDC：`projectId`、`userId`、`traceId`。
- 优雅停机：`ProjectRegistry.closeAll()` 等待修订落盘线程完成。
  - 已实现（S3）：`server.shutdown: graceful` 先让进行中的请求完成；之后 Spring 按 bean 依赖先调 `closeAll()`，再关闭 `KernelExecutors`。顺序不能反：每个项目的写盘任务是串起来的，线程池先关闭会让后面的修订被拒绝、丢失。
