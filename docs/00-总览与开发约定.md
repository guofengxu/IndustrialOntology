## 2. 新仓库结构

```
IndustrialOntology/
├── pom.xml                         # 父 POM：revision=0.1.0-SNAPSHOT，导入 spring-boot-dependencies 3.5.x
├── wp-kernel-api/                  # OWL 变更模型、索引接口、修订接口、层级接口（← webprotege-server-api）
├── wp-kernel/                      # 索引实现、IndexUpdater、ChangeManager、RevisionStore、ProjectContext、
│                                   #   Lucene 字典、层级 Provider、帧翻译、渲染、EntityCrudKit（← server-core/lucene）
├── wp-domain/                      # 纯 DTO（record）：帧、表单描述符、匹配条件、设置、事件（← webprotege-shared 去 GWT）
├── wp-app/                         # 按功能切分的应用服务 + Spring Data Mongo 仓库 + 权限 + 事件总线
├── wp-api/                         # Spring MVC 控制器 /api/v1、兼容层 /data、SSE、OpenAPI、Security 配置
├── wp-integration/                 # 集成 REST（运行数据 / 类 / 属性），兼容路径 + v1 路径
├── wp-governance/                  # P3：版本标签、对比回滚、发布校验 StateGraph、模型注册 /registry
├── wp-ai/                          # P4（可选）：本体助手 Agent、MCP Server
├── wp-server/                      # Spring Boot 可执行应用：main、application.yml、打包前端静态资源
├── wp-cli/                         # 管理命令：create-admin、generate-api-key、rebuild-permissions、migrate-mongo
├── wp-web/                         # React 前端（pnpm）
├── deploy/                         # Dockerfile、docker-compose（mongo、keycloak、app）、keycloak realm 导出
├── docs/                           # 本套文档 + ADR
└── .cursor/                        # rules + skills（从旧仓库迁入并改写）
```

Maven 依赖方向（只能向下）：

```
wp-server → wp-api, wp-integration, wp-governance, wp-ai, wp-cli(独立 jar)
wp-api / wp-integration / wp-governance / wp-ai → wp-app → wp-kernel → wp-kernel-api → wp-domain
```

- `spring-ai-alibaba-bom` 只在 `wp-governance` 与 `wp-ai` 的 POM 中引入；`wp-kernel*`、`wp-domain`、`wp-app`、`wp-api` 的 POM 不得出现 `com.alibaba.cloud.ai` 或 `org.springframework.ai`。父 POM 用 `maven-enforcer-plugin` 的 `bannedDependencies` 固化这条规则。
- 可选 Spring Modulith：`wp-app` 内按功能包划分为 `project`、`access`、`frame`、`form`、`search`、`hierarchy`、`issues`、`tag`、`watch`、`perspective`、`io`、`event`，`ApplicationModules.verify()` 作为测试跑。

包根：`org.industrial.ontology`（groupId 与之相同；后缀按模块：`kernel.api`、`kernel`、`domain`、`app.<feature>`、`api`、`integration`、`governance`、`ai`）。

## 4. 编码规范（后端）

参照 spring-ai-alibaba 框架库，**不参照其 Admin 平台**。

1. 构造器注入，`final` 字段；不用字段注入，不用 Lombok，不用 MapStruct。
2. DTO 一律 Java `record`；跨进程 JSON 用 Jackson 注解显式字段名。
3. 领域对象不可变；集合用 `List.copyOf` / Guava `Immutable*`。
4. 日志 SLF4J `LoggerFactory.getLogger(X.class)`，占位符参数，不拼接。
5. 异常：业务异常继承 `WpException(code, httpStatus)`；控制器不 try/catch，统一 `@RestControllerAdvice` 输出 RFC 7807 `application/problem+json`。
6. Javadoc：公共类型与非自明公共方法写英文 Javadoc 说明"为什么"；注释不复述方法名。
7. Checkstyle 使用 spring-ai-alibaba 的 `tools/src/checkstyle/checkstyle.xml` 去掉 RegexpHeader（本项目无 Apache 头要求）；Spotless `removeUnusedImports`；spring-javaformat 关闭（保留 4 空格缩进）。
8. 测试类命名 `XxxTest`（单元）、`XxxIT`（集成，Testcontainers，failsafe 跑）；不用 `_TestCase` 后缀。需要 Mongo 的测试统一用 `wp-app` 测试 jar 中的 `MongoTestServer`：有 Docker 时启动 `mongo:7.0` 容器，没有时退回内存实现 mongo-java-server；`-Dwp.test.mongo=container|memory|<mongodb:// 连接串>` 可强制指定，CI 用 `container`，避免 Docker 出问题时悄悄退回内存实现。
9. 并发：项目级写锁语义保持（见 `01` 文档 3.4）；禁止在持有写锁时做 IO 以外的阻塞等待。
10. 不引入 Reactor 到 `wp-kernel*`/`wp-app`；SSE 在 `wp-api` 用 `SseEmitter`。

## 5. 编码规范（前端）

1. 函数组件 + hooks；TypeScript `strict`；禁止 `any`（用 `unknown` + 类型守卫）。
2. 服务端状态用 TanStack Query，key 规范 `['project', projectId, 'frames', 'class', iri]`；客户端状态用 zustand（selection、layout 编辑态）。
3. API 客户端由 OpenAPI 生成（`openapi-typescript` + 轻量 fetch 封装），不手写 DTO。
4. 组件目录按功能：`src/features/<feature>/{api,components,hooks,model}`；Portlet 在 `src/portlets/<id>/`。
5. 文案全部走 `react-i18next`，键名 `feature.component.text`；首期 `zh-CN`、`en`。
6. ESLint（typescript-eslint + react-hooks）+ Prettier；提交前 lint-staged。
7. 测试：Vitest + Testing Library（组件）、Playwright（端到端，P2 起）。

## 6. Git 与提交约定（沿用旧仓库规则）

- 分支：`<type>/<ticket>-<kebab>`，type ∈ feature | fix | hotfix | test | refactor | docs | chore | release。
- 提交与 PR 标题：Conventional Commits。
- Issue/PR 评论：Conventional Comments。
- 任务编号作为 ticket：如 `feature/P0-03-index-port`。
- 默认分支 `main`，禁止直推；PR 需 CI 绿（format → checkstyle → test → build → web lint/test）。

## 7. Cursor 工作规则（迁入新仓库 `.cursor/rules/IndustrialOntology.mdc`）

```markdown
---
description: WebProtégé NG 开发规则
alwaysApply: true
---
1. 任务入口是 docs/05-任务拆分与验收.md；每个任务只做其"产出"列出的文件，不顺手重构无关代码。
2. 依赖方向：server → api/integration/governance/ai → app → kernel → kernel-api → domain。违反即失败。
3. wp-kernel*、wp-domain、wp-app、wp-api 禁止依赖 spring-ai-alibaba / spring-ai。
4. 本体公理只经 ChangeManager.applyChanges 写入；读只走索引；Mongo 不存公理。
5. 项目级对象（索引、ChangeManager、RevisionStore、Lucene、EventManager）不是 Spring bean，由 ProjectContextFactory 构造。
6. 新增 REST 端点必须：OpenAPI 注解、权限动作声明、Problem JSON 错误、至少一个 WebMvcTest。
7. 迁移自旧仓库的代码保留原类名（去掉 Impl 后缀除外）并在 Javadoc 首行注明 `Ported from edu.stanford...`。
8. 前端：Portlet 必须在 src/portlets/registry.ts 注册，id 与 docs/03 的清单一致。
9. 不做：OBO、Collections、Slack、CSV 导入、GWT 兼容层。
10. 每个任务结束运行 `mvn -q verify -pl <module> -am` 与 `pnpm -C wp-web test`，输出贴进 PR。
```

旧仓库的 `.cursor/skills/git-naming-conventions` 原样迁入；`deploy-webprotege`、`generate-apikey`、`webprotege-code-dev` 三个技能作废，由新仓库的 `deploy-ng`（compose up）与 `wp-cli` 替代。

## 8. 运行配置（`wp-server/src/main/resources/application.yml` 骨架）

```yaml
server:
  shutdown: graceful                                     # 请求先完成，再 ProjectRegistry.closeAll()（01 §7）
spring:
  application.name: IndustrialOntology
  data.mongodb.uri: ${WP_MONGODB_URI:mongodb://localhost:27017/webprotege}
  security.oauth2.resourceserver.jwt.issuer-uri: ${WP_OIDC_ISSUER:http://localhost:8180/realms/webprotege}
  servlet.multipart.max-file-size: ${WP_MAX_UPLOAD:200MB}
  mail:
    host: ${WP_SMTP_HOST:}
    port: ${WP_SMTP_PORT:587}
    username: ${WP_SMTP_USER:}
    password: ${WP_SMTP_PASSWORD:}
webprotege:
  mongo.ensure-indexes: true                             # 启动时补建缺失的旧版索引（MongoIndexes，S4）；wp-cli 中为 false
  data-directory: ${WP_DATA_DIR:/srv/webprotege}        # 与旧 data.directory 同布局
  project.dormant-time: ${WP_PROJECT_DORMANT:PT1H}       # 旧 project.dormant.time
  events.retention: PT10M                                # 旧为 60s
  events.max-batch: 200
  kernel:                                                # 所有项目共享的线程池（KernelExecutors，S3）
    index-update-threads: 10                             # 旧 INDEX_UPDATING_THREADS
    revision-write-threads: 4
  auth:
    api-key.enabled: true
    local-login.enabled: ${WP_LOCAL_LOGIN:false}         # 仅 dev/admin 兜底
    admin-realm-role: webprotege-admin                   # Keycloak realm role → SYSTEM_ADMIN
  compat:
    legacy-data-api.enabled: true                        # /data/* 兼容层，淘汰期后关闭
    legacy-hash-routes.enabled: true
  governance:
    enabled: false                                       # P3 打开
  ai:
    enabled: false                                       # P4 打开
management:
  endpoints.web.exposure.include: health,info,metrics,prometheus
  otlp.tracing.endpoint: ${OTEL_EXPORTER_OTLP_ENDPOINT:}
```

旧 `webprotege.properties` 的三个键映射：`data.directory` → `webprotege.data-directory`；`project.dormant.time` → `webprotege.project.dormant-time`；`application.version` → `info.app.version`（来自 build-info）。

## 10. 完成定义（Definition of Done）

一个任务视为完成，需同时满足：

1. 代码合入 `main`，CI 全绿。
2. `05` 文档中该任务的验收标准逐条有证据（测试名或手工步骤记录）。
3. 新增/变更的 REST 端点出现在 `/v3/api-docs` 且 `02` 文档同步更新。
4. 迁移自旧仓库的代码，其对应旧测试已转换为 JUnit 5 并通过（允许标注 `@Disabled("not ported: <reason>")` 但需列入 PR 描述）。
5. 无新增 Checkstyle / ESLint 告警。
